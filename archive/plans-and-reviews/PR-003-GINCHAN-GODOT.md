# PR-003｜銀醬：本機 3D 角色與 Godot 動畫

狀態：完整可動 3D 首版已交付，包含真正的 MotionBricks 生成動作與 Windows 展示程式；外觀仍是粗修首版，尚未經使用者評定造型品質。
更新日期：2026-11-07。
角色：銀醬；署名沿用 hozumi。唯一外觀基準：[new.png](../new.png)。
閱讀入口：[圖解工作計劃與容量](PR-003-GINCHAN-PLAN.html)。

## 需求與核心決策

使用者優先希望看到銀醬的 3D 角色在 Godot 裡動起來。保留免費、盡量本機運算及 MotionBricks 本機生成動畫後再匯入的方向。2D 可在需要時協助準備參考或貼圖，不另開 Live2D／拆圖模型製作線。

主流程：三視圖 → Pixal3D INT8 多視角粗模 → Blender 修模、骨架與表情 → GLB → Godot 4.6.3。先打通基本動作與 Godot 播放，再接 MotionBricks；錄音表情 Audio2Face 延後為選配。一次只有一個目標執行。

此 PR 是需求與執行計劃文件。使用者於 2026-11-07 明確授權開始完整 3D 首版、下載所需模型及啟動本機服務；目標包含 MotionBricks，不能以基本動作測試代替最終交付。

## 首版範圍與交付

首版是單一角色展示專案，不加入遊戲關卡、戰鬥、網路或完整操控系統。展示場景提供觀看角度、播放／暫停與動畫切換，讓使用者看清楚角色是否真正可動。

交付：可編輯 Blender 原檔、自含或成套貼圖的 GLB、Godot 4.6.3 專案、Windows 展示程式、關鍵視角 PNG 和短錄影。規劃位置：
- blender/ginchan-character.blend
- exports/ginchan.glb
- godot/project.godot
- builds/windows/（放在 Godot 專案目錄外）
- renders/（外觀與動作驗收證據）

第一個可動版本包含基本身體動作與眨眼；完整首版增加 MotionBricks 生成的站立、起步、走幾步、停下過渡。指定目標姿勢和路徑後離線生成，做骨架對應與動畫烘焙。Godot 播放生成結果，不同時載入模型推理。

首版不要求 VRM／Live2D 格式、攝影機直播、語音對嘴、完整 52 項臉部形變、手指捕捉或複雜頭髮布料模擬。這些依成品需求再加入。

### 目標 1：輸入與粗模

- 保留 new.png 原檔，用工作副本準備三視角；核對正、側、背位置、頭頂／腳底比例。去掉標題與背景對生成的干擾；去背後特別檢查淡色髮絲。
- 先使用目前圖像；若手臂或腿部黏連無法合理分開，再準備同一角色的 A 姿勢參考。需要補圖或修改圖片時使用內建 image_gen，不默默變更服裝、髮型或身體比例。
- 安裝時確認 ComfyUI 版本包含官方 Pixal3D 多視角節點；記錄版本與模型檔。不把其他工作專案的環境升級作為先決條件。
- 選多視角 INT8，只下載一個主模型、兩個 VAE、DINOv3 和 BiRefNet；不同時下載單圖 Pixal3D、TRELLIS.2 或訓練資料。
- 依工作流程可用設定從較低解析度測試，記錄 GPU／RAM 峰值及生成時間；一次只有一套重模型運作。
- 先生成一個粗模，對已觀察到的問題做一次有理由的修訂。若兩次仍嚴重黏連或顯示記憶體不足，停止增加同類嘗試，評估 Hunyuan3D-2mv 形狀生成或 Blender 局部重建。
- 技術驗收：可開啟網格，角色正面身份可辨認，手腳輪廓可分離，頭髮與服裝具備可修整的基礎。此時不宣稱已完成可用遊戲角色。

### 目標 2：先在 Godot 看見她動

- Blender 先清理影響變形的重大黏連，對齊人體骨架並測基本權重；手動關鍵格只用於驗證鏈路。
- 匯出帶骨架動畫的 GLB，建立最小 Godot 展示場景。用固定地面、燈光和可觀看角色的鏡頭測試，不建立完整遊戲。
- 先驗收抬臂或站姿變化，以及轉動鏡頭後角色仍有完整體積。讓轉檔、尺寸、方向、骨架、材質問題提早出現。
- 這段測試動畫不算 MotionBricks 驗收，後續仍要真正生成動作。

### 目標 3：造型與可動結構

- Blender 對照三面圖修正頭身比例、側臉、短髮與兩側長髮束、肩帶、短褲輪廓及腳部；需要時局部重建。
- 整理肩、肘、髖、膝周圍可彎曲的網格；減面或自動重建網格不等同完成動畫拓撲。
- Rigify 可協助建立控制骨架，骨頭位置和權重仍要校準。保留日後對應 SOMA／Godot 人體骨架的名稱及姿勢紀錄。
- 頭髮與身體適當分開。初版髮束隨頭部／對應骨骼運動；自然晃動另加次級骨骼動畫或 Godot 物理，不假設 Blender 模擬會自動隨 GLB 匯出。
- 眼球、眼皮、眉與嘴部做成可動結構。先做中立、左右眨眼、張嘴、微笑和必要眉形，不先強制製作完整 52 通道。
- 在 Godot 調整柔和卡通材質；Blender 複雜節點材質不保證原樣轉移。先用少量材質、合理貼圖解析度和適中網格，再依畫面與效能調整。
- 驗收正面、側面、背面、45° 圖，與肩肘膝彎曲、眼睛半閉及全閉、嘴巴開合短片；技術成立與使用者對外觀的接受分開記錄。

### 目標 4：MotionBricks

- 採 SOMA 人類模型，不裝機器人分支。先準備自己的中立站姿、起步、行走和停止目標姿勢。
- 模型輸入是近期姿勢、目標姿勢和運動限制，不是自然語言指令。單次產生短過渡，長片段要串接。
- 對應 SOMA 的 30 關節到銀醬骨架；校正比例、休息姿勢、坐標、朝向、根部位移與接地。只改骨頭名稱不足以保證對應正確。
- 在 Blender 烘焙動作，再輸出同一套骨架的 GLB 動畫給 Godot，避免同時維護兩套重定向。
- 檢查腳滑、腳底穿地、膝蓋反折、肩部崩壞、頭髮穿身及過渡跳動。必要時修關鍵格，不宣稱 AI 動作不需清理。
- 官方附帶動作範例只作相應條款允許的測試，不作成品動畫庫；保存自建輸入、模型版本及真正的生成結果。

### 目標 5：交付與重開

- 清楚保存角色源檔、貼圖、輸出 GLB 與 Godot 專案；每種角色版本有明確用途，避免 final2 等不明副本。
- 重開 Blender，重匯 GLB；重開 Godot 專案並播放基本表情和生成動作。
- 用既有 4.6.3 Windows 模板輸出展示程式，在此機啟動驗收；不把只有編輯器內播放視為 Windows 成品已完成。
- 以 1080p 單角色場景記錄實際幀率、貼圖和網格資源；以流暢播放為目標，不在未實測前承諾固定幀率或下載後即完成。

## 容量預算

完成後實測：指定工作資料夾邏輯大小合計約 **28.39 GB**，其中 uv 安裝快取 9.41 GB；硬連結可能重複計數，未包含既存共用軟件和全域快取。C 槽約剩 **179.45 GiB**。[明細](../logs/storage-report.json)。以下保留原始規劃預留量，與實際佔用區分。

容量為 GB 十進位規劃值，非 VRAM。模型權重由官方公開檔案大小計算，環境與快取為預留量。

- 先做 Godot 基本可動版本：新增空間預留約 35–60 GB。
- 加上 MotionBricks 的完整 3D 首版：新增空間預留約 40–75 GB。
- 再加 Audio2Face：新增空間預留約 50–95 GB。
- 2D 製作工具目前新增 0 GB。See-through、Anime2.5DRig、Cubism、VTube Studio、PNGAL、Qwen 分層模型均不列入下載清單。
- Hunyuan3D-2mv 是失敗時備案，獨立原始環境路線約 12–20 GB；能否共用 ComfyUI 與所選檢查點大小，切換前再核算。不要現在加裝，也不要將備案全部加進必需容量。
- 不重複下載同一模型的單圖／多圖版本、不同精度或訓練資料。工程備份和長影片可能超過上述起步預算。

五份權重：多視角主模型 5.5846 GB、DINOv3 1.2152 GB、形狀 VAE 1.0958 GB、材質 VAE 0.9485 GB、BiRefNet 0.4445 GB，合計 9.2885 GB。2026-11-07 已全部下載且 SHA-256 校驗通過。

## 執行邊界與下一步

使用者已明確授權下載所需模型及啟動本機服務。服務僅綁定 127.0.0.1，不對外暴露。優先沿用現有本機工具，其餘模型按階段下載。沒有收費服務、雲端角色上傳或帳號訂閱。

目標 1–5 的可動首版已完成，入口在 [README](../README.md)。ComfyUI 空佇列後已停止，成品播放不依賴推理服務。後續若繼續改善，優先對照原圖精修臉部、髮絲、上衣貼色與關節拓撲；本次未自動擴充直播、語音或 2D 製作線。
